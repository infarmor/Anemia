# Восстановление сети и сетевая безопасность Anemia

Этот документ — про то, **почему раньше Mac мог остаться без интернета** после
сбоя Anemia и **как устроена защита сейчас** (хелпер 0.8.0+). В конце — что
делать, если сеть всё-таки не работает.

## Что ломало сеть раньше

Привилегированный хелпер меняет системные настройки, и часть из них
**переживает перезагрузку**:

| Изменение | Где хранится | Переживает reboot |
|-----------|--------------|-------------------|
| DNS сервиса (`networksetup -setdnsservers`) | SystemConfiguration preferences | **да** |
| SOCKS-прокси сервиса (`networksetup -setsocksfirewallproxy`) | SystemConfiguration preferences | **да** |
| Маршруты `0/1`, `128/1`, host-bypass | ядро | нет |
| pf kill switch | ядро | нет |

До 0.8 резервные копии DNS/прокси вели себя опасно:

1. Файл бэкапа **удалялся даже при неудачном восстановлении** — сервис оставался
   с DNS `172.28.0.2` (адрес туннеля, которого уже нет).
2. Следующая сессия видела «нет бэкапа» и **сохраняла этот мёртвый DNS как
   настройку пользователя** — и каждое последующее «восстановление» заново
   прописывало его.
3. DNS и прокси менялись **на всех сервисах, включая VPN-сервисы** (например,
   Happ), и даже на тех, чьё состояние не удалось прочитать.
4. Kill switch **заменял основной набор правил pf** и при отключении
   перезагружал `/etc/pf.conf`, сбрасывая якоря других системных служб.
5. При удалении хелпера из приложения **DNS не восстанавливался вовсе**.

Итог — DNS или прокси, указывающие в никуда, сохранялись через любые
перезагрузки: браузеры и приложения «без интернета», хотя сама сеть исправна.

## Как это устроено сейчас

**Журнал изменений** (`/var/db/Loader/network-journal.json`, root, 0600):

- исходное значение записывается и **сбрасывается на диск (fsync) до**
  изменения настройки; нет записи — нет изменения;
- в журнал **никогда не попадают наши собственные значения** (DNS в диапазонах
  туннеля, прокси на порту движка) — мёртвый пин не может стать «настройкой
  пользователя»;
- запись удаляется только после успешного восстановления **или** если
  пользователь сам изменил настройку после нас (её не трогаем);
- сервисы без аппаратного устройства (VPN-сервисы вроде Happ) и сервисы с
  нечитаемым состоянием **не трогаются**.

**Хелпер восстанавливает сеть при каждом запуске** — при загрузке системы
(`RunAtLoad`), после краша (launchd перезапускает его: `KeepAlive`
`SuccessfulExit=false`), при переустановке: откатывает журнал, снимает kill
switch, убивает осиротевшие `tun2socks`/`amneziawg-go`, удаляет маршруты на
несуществующих utun, сбрасывает DNS, указывающие на туннель, которого нет.
**Любая перезагрузка возвращает Mac к рабочей сети.**

**Kill switch** живёт в собственном якоре pf `com.apple/000.AnemiaKillSwitch`:
основной набор правил не заменяется, отключение — это очистка одного якоря.
Правила stateless (`no state`), поэтому уже открытые соединения не рвутся при
включении. Корректность синтаксиса проверяется в тестах настоящим `pfctl -n`.

**Сторож (watchdog)**: если системный прокси указывает на порт, где никто не
слушает, или DNS переключён на туннель, которого нет, — через 15 секунд хелпер
сам всё возвращает (приложение зависло, убито и т.п.).

**SIGTERM** (выключение, `launchctl bootout`, удаление) — полный корректный
откат, а не просто остановка процесса.

**Split tunneling (обход VPN)** не добавляет постоянных настроек: маршруты для
перечисленных сетей и доменов живут только в ядре на время сессии, снимаются
при отключении и не переживают перезагрузку. Записи, которые выключили бы VPN
целиком (слишком широкие сети, loopback, диапазоны самого туннеля), отклоняются
и в приложении, и повторно в хелпере.

**Системный прокси по умолчанию выключен.** Если полный туннель невозможен,
потому что маршруты занял другой VPN, приложение предложит включить маршрутизацию
приложений через Anemia — но только по вашему выбору.

## Если сеть не работает

1. **Приложение → Настройки → Network safety → Repair network settings.**
   Работает даже без установленного хелпера (один запрос пароля
   администратора). Главное окно само показывает баннер, если находит
   «мёртвые» DNS или прокси.
2. **Без приложения** — из Терминала:

   ```bash
   sudo bash Scripts/anemia-network-reset.sh
   ```

   Скрипт не требует ничего, кроме стандартной macOS (bash 3.2, plutil,
   networksetup, pfctl): снимает kill switch, останавливает осиротевшие
   процессы, удаляет мёртвые маршруты, восстанавливает DNS/прокси из журнала и
   сбрасывает те, что указывают в никуда. С флагом `--uninstall` дополнительно
   удаляет хелпер.
3. **Перезагрузка** при установленном хелпере 0.8+ тоже восстанавливает сеть
   (хелпер откатывает журнал при старте).

Проверить состояние вручную:

```bash
networksetup -getdnsservers Wi-Fi
```

```bash
networksetup -getsocksfirewallproxy Wi-Fi
```

```bash
sudo pfctl -a com.apple/000.AnemiaKillSwitch -s rules
```
