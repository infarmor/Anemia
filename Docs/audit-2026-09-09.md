# Аудит логики Anemia (Loader) — 2026-09-09

Полный аудит: helper (root-демон, XPC, pf, маршруты), приложение (AppState, подключение,
recovery, подписки, ML-ранкер), парсер share-линков, конфиг-билдер Xray, вьюхи и скрипты.
Сборка после всех правок: `swift build -c debug --arch arm64` — **зелёная**; тесты — см. ниже.

Состояние каждой находки: **ИСПРАВЛЕНО** / **ДОКУМЕНТИРОВАНО** (принято осознанно, с причиной).

### ДОКУМЕНТИРОВАНО

- **H3 (ClientVerifier TOCTOU)**: между `SecCodeCopyGuestWithAttributes` и проверкой требования
  код подписи теоретически может быть подменён; на практике окно наносекундное и атакующий уже
  должен быть рутом соседнего процесса. Принято как осознанный риск; полноценное закрытие требует
  перепроверки в момент каждого вызова XPC-метода.

## 2. Приложение (AppState, connect, recovery, подписки, история)

### ИСПРАВЛЕНО

| # | Проблема | Отказ | Файл |
|---|----------|-------|------|
| 1 | `connect()` не разбирал предыдущую сессию (гонка «connect на connect») | Два движка, два туннеля, рассинхрон epoch | `AppState.connect(isReconnect:)` — полный teardown перед стартом |
| 2 | Health-луп гейтился `killSwitchEnabled` | Мёртвый upstream + kill switch = вечный блэкхоул без recovery | `AppState.swift` — гейт снят, recovery идёт с keepTunnel |
| 3 | Ротация app.log падала при существующем `.log.1` | Логи переставали писаться | `AppLog` — removeItem перед moveItem; formatter → `nonisolated(unsafe) static let` |
| 5 | Несвежие `pings`/`learnedMasking` росли бесконечно | Разрастание state.json | `pruneHistory()` — collect-then-delete (заодно устранил мутацию при итерации словаря), чистка learnedMasking по живым identityKey, вызов после refresh подписок |
| 6 | Launch-sweep убивал чужой активный туннель при старте поверх подключённого состояния | Туннель падал при повторном запуске приложения | guards `isConnected == false` |
| 7 | Подписки: без таймаута сессия и перезапуск цикла рвал живой | «Вечное» обновление подписки | ephemeral `subscriptionSession` (20/30 c, no-cache); неразрушающий restart цикла |
| 10 | `osascript`-пайп не читался | Заполнение 64 КБ пайпа → вечный `helperBusy` | `runScriptAsAdmin` → `FileHandle.nullDevice` |
| 14 | `ISO8601DateFormatter` как static var | Data race предупреждение | `nonisolated(unsafe) static let` |

### ДОКУМЕНТИРОВАНО

- **#4 (пинги через собственный туннель)**: пока туннель поднят, пинги/latency-probe уходят в
  туннель и измеряют не сервер, а путь через туннель. Не исправлено — правильное решение требует
  привязки probe-сокетов к физическому интерфейсу (аналог `sockopt.interface`) в `pingAll`/
  `LatencyProbe`; отдельная инженерная задача.
- **#8 (keepTunnel + смена порта движка)**: recovery сохраняет туннель, а `PortFinder` возвращает
  preferred-порт — конфликт теоретически возможен, но покрыт ретраями recovery-лестницы.
- **#9, #11–#13**: инфраструктурные замечания (сортировка в UI, дублирование конфиг-полей) —
  косметика, не влияет на логику.
